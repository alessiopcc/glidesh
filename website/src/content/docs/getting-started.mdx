## Prerequisites

- SSH access to target machines (key-based authentication)
- No agent or runtime required on target hosts

## Installation

<Tabs>
  <TabItem label="Linux">
    ```bash
    curl -fsSL https://glidesh.netlify.app/install.sh | sh
    ```

    Installs the latest release to `~/.local/bin` (`/usr/local/bin` as root), after checking
    it against the release's SHA-256 sums. The Linux binary is static: it runs on any
    distribution. [Homebrew](https://brew.sh) works too, as on macOS.
  </TabItem>
  <TabItem label="macOS">
    ```bash
    brew install alessiopcc/tap/glidesh
    ```

    Or, without Homebrew, the same script as on Linux:

    ```bash
    curl -fsSL https://glidesh.netlify.app/install.sh | sh
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    scoop bucket add alessiopcc https://github.com/alessiopcc/scoop-bucket
    scoop install alessiopcc/glidesh
    ```

    With [Scoop](https://scoop.sh). Windows binaries for x64 and arm64 are also on the
    release page (see below).
  </TabItem>
</Tabs>

### Upgrade and uninstall

| Installed with | Upgrade | Uninstall |
|---|---|---|
| `install.sh` | run it again | `rm ~/.local/bin/glidesh` |
| Homebrew | `brew upgrade glidesh` | `brew uninstall glidesh` |
| Scoop | `scoop update glidesh` | `scoop uninstall glidesh` |

### Script options

The script takes its options from the environment; `sh install.sh --help` lists them.

```bash
# A given version, into a directory of your choice
curl -fsSL https://glidesh.netlify.app/install.sh | GLIDESH_VERSION=v2.0.0 GLIDESH_INSTALL_DIR=/opt/bin sh
```

It never runs `sudo`: to install into a system directory, run it as root. To read it before
running it, download it first: `curl -fsSLO https://glidesh.netlify.app/install.sh`.

### Manual download

Every [GitHub release](https://github.com/alessiopcc/glidesh/releases) has one archive per
target, named `glidesh-<version>-<target>.tar.gz` (`.zip` on Windows), and
`checksums-sha256.txt` to verify them against:

| System | Target |
|---|---|
| Linux x86_64 / arm64 | `x86_64-unknown-linux-musl` / `aarch64-unknown-linux-musl` |
| macOS Intel / Apple silicon | `x86_64-apple-darwin` / `aarch64-apple-darwin` |
| Windows x64 / arm64 | `x86_64-pc-windows-msvc` / `aarch64-pc-windows-msvc` |

The archive holds the single `glidesh` binary (`glidesh.exe`); put it on your `PATH`.
Releases before 2.0 built Linux against glibc (`-unknown-linux-gnu`).

### From source

Requires Rust 1.86+.

```bash
git clone https://github.com/alessiopcc/glidesh.git
cd glidesh
cargo build --release
```

The binary will be at `target/release/glidesh`.

## Quick Start

### 1. Define your inventory

Create an `inventory.kdl` file listing your target machines:

```kdl
vars {
    deploy-user "deploy"
}

group "web" {
    host "web-1" "192.168.1.10" user="deploy" port=22
    host "web-2" "192.168.1.11" user="deploy"
}
```

### 2. Write a plan

Create a `plan.kdl` describing the desired state:

```kdl
plan "setup-web" {
    step "Install nginx" {
        package "nginx" state="present"
    }

    step "Start nginx" {
        systemd "nginx" {
            state "started"
            enabled #true
        }
    }
}
```

### 3. Run it

A plan says *what* to do; the command line says *where*. `-t web` runs it on the `web`
group:

```bash
glidesh run -i inventory.kdl -p plan.kdl -t web
```

Add `--dry-run` to preview changes without applying them:

```bash
glidesh run -i inventory.kdl -p plan.kdl -t web --dry-run
```
